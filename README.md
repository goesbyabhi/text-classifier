# text-classifier

Zero-shot text classification over plain HTTP. Send **text + labels** in, get
a **label and a calibrated confidence** out. No API key, no fine-tuning, no
per-request model training — a frozen embedding model and a request-time
linear read, the confidence made honest by a calibration fit on a holdout.

Built as a **Cloudflare Python Worker** ([pywrangler](https://developers.cloudflare.com/workers/runtime-apis/python/)),
modeled on classifier.dev. Everything here is measurable: eval numbers come
only from `eval/`.

```sh
# the whole thing, once
curl -s https://your-worker.workers.dev/v1/classify \
  -H 'content-type: application/json' \
  -d '{"inputs": ["Win a free iPhone"], "labels": ["spam", "not spam"]}'
```

```json
{
  "label": "spam",
  "confidence": 0.9912,
  "scores": { "spam": 0.9912, "not spam": 0.0088 },
  "ms": 210,
  "model": "@cf/baai/bge-small-en-v1.5"
}
```

## How it works

```
text ──► embed ──► normalised 384-dim vector ──┬──► cosine similarity ──► softmax(T) ──► P(label)
labels ─► embed ──► normalised 384-dim vector ─┘                                        └──► sigmoid(bias,T) for multi
```

1. **Embed.** Every input and every label is embedded once with a frozen
   sentence-embedding model (Workers AI `bge-small-en-v1.5` in the Worker; a
   deterministic `hash-v0` feature-hashing stand-in for tests and eval, so
   everything runs offline with no account).
2. **Score.** A prototypical linear read — the cosine similarity between the
   text embedding and each label embedding. No learned weights at request
   time. The label embedding *is* the class model, which is why this is
   zero-shot: new labels need no training, just an embedding.
3. **Calibrate.** Raw cosine similarities are not probabilities. The
   single-label softmax gets a temperature, the multi-label sigmoid gets a
   bias and temperature, and the multi boundary gets a threshold — all fit on
   a held-out calibration set and shipped with the Worker: `scripts/train.py`
   for the offline hash-v0 fit, `scripts/train_bge.py` for the real
   fit against deployed bge embeddings via Workers AI. The point: **the
   confidence you are quoted is the frequency you would see**, not a vibe.

That calibration is the part most services skip. A forced softmax always has
to pick something, so alongside the calibration the scorer **withholds** its
numbers for input that does not read as natural language (the `unintelligible`
heuristic), because publishing a confident score for `asdkjfhkasjdhf` would
invite callers to threshold on noise.

### The math keeps this small on purpose

- numpy only, so it runs inside the Worker (WASM); no torch/transformers.
- Top-level module code runs once at deploy (the Worker snapshot) — the
  scorer, embedder wrapper and calibration are built at import, not per
  request.

## Layout

```

src/classifier.py      the numpy scorer + calibration fitting (pure, tested)

src/benchmark_data.py  generated by train_bge.py from eval/results (gitignored)
src/skill.py           the agent skill (/skill.md) + RFC-8615 discovery index
scripts/train.py       offline hash-v0 calibration fits (local, no account)
scripts/train_bge.py   real bge fits via Workers AI + eval holdout judgment

eval/data/             labeled datasets (gitignored)

cli/classify.py        classify lines from stdin
mcp/classify_server.py MCP server exposing a classify_texts tool
tests/                 70 pytest tests on the pure modules
```

## Run it

```sh
uv run pytest                          # 70 tests, pure modules
uv run python scripts/train.py eval/data/calibration.jsonl   # offline hash-v0 fit
uv run python eval/bench.py eval/data/eval.jsonl             # judge the math
uv run pywrangler dev --local          # boot the Worker locally
uv run pywrangler deploy               # after copying wrangler.example.toml → wrangler.toml
```

Point a browser at `http://127.0.0.1:8787/` in dev to get the landing page
with the live demo box (type a sentence and labels, click classify); `curl`
gets the same document as plain text. Both come from one source — `src/docs.py`
— so they cannot drift.

Note: `pywrangler dev` needs uv >= 0.12.3 (`uv self update`). In local dev the
AI binding reports "not supported", so classify returns the designed 502
there — the scorer math is covered by pytest instead. Once you have a
Cloudflare account, `wrangler secret put` and the AI binding work for real.

## API

- `POST /v1/classify` — batch JSON. `{"inputs": [...], "labels": [...], "multi": true, "max_labels": 3}`
- `GET /{labels}/{text}` — e.g. `/spam,not+spam/Win+a+free+iPhone` (plain text answer)
- `GET /?labels=spam,not+spam&text=...` — query spelling
- `GET /` — docs. `GET /health`, `GET /openapi.json`
- `GET /benchmark` — the measured numbers, plain text (generated from eval, never hand-typed)
- `GET /skill.md`, `GET /.well-known/agent-skills/index.json` — agent skill + RFC-8615 discovery (digest = sha256 of the served bytes)
- `mcp/classify_server.py` — MCP server exposing `classify_texts` (make an HTTP call per request)

Limits per IP (Durable Object, never KV): fast `3,000/min, 20,000/day`,
smart `200/min, 2,000/day`. Input text is never stored or logged; analytics
carry tier/labels-fingerprint/status/latency only.

## Where it plugs in — real ways to use it

These are the things people actually do with a zero-shot classifier: run it
over a batch, route on a calibrated threshold, and let a human own the parts
it is honestly unsure about. Each example runs two ways — offline against the
hash-v0 stand-in (no account), or `--endpoint` against a deployed Worker:

```sh
uv run python examples/hn_headlines.py            # offline pattern
uv run python examples/hn_headlines.py --endpoint http://127.0.0.1:8787
```

### 1. Bucket the Hacker News front page, flag the unsure ones

`examples/hn_headlines.py` fetches the live front page, classifies all 30
titles into `ai / security / business / hardware / other` **in one request**,
prints the bucket counts, then the three stories the model is least confident
about — the ones to read before believing the bucket.

### 2. Triage a support inbox, human only when confidence is honest

`examples/support_triage.py` routes `billing → finance`, `bug → eng`,
`feature → product` and labels everything below `--bar` confidence
**HUMAN DOUBLE-CHECK**. The bar is the point: a calibrated 0.6 means 60%,
and the automation refuses to trust worse than that. Change the bar, change
nothing else.

### 3. The agent-skill case: keep 6 of 40 search results

The reason to call out is *context, not capability* — you are already a model
and can see the snippets yourself, so the expensive part is the reading.
`examples/agent_context.py` takes a working question, keeps only the snippets
that are about it, returns them in original order, and *when in doubt, keeps*:
near-boundary items survive because dropping a relevant result costs more than
reading one extra.

### 4. Multi-label tag a changelog

`examples/changelog_tags.py` tags every entry with *every* label that applies
(`language, compiler, library, tooling, platform`) — an entry can be a library
note *and* a language change, which a single forced label would hide.

### 5. One-shot CLI in a pipeline

```sh
classify spam,not+spam < feedback.txt            # one label per line
cat tickets.txt | classify --multi bug,feature,praise
```

### 6. An MCP tool for agent hosts

`mcp/classify_server.py` is a stdlib-only MCP server exposing one tool,
`classify_texts` (inputs + labels in, results out), that proxies to the API:

```sh
python mcp/classify_server.py --endpoint https://your-worker.workers.dev
```

Point any MCP host at it (`.mcp.json`: `"command": "python", "args": ["mcp/classify_server.py"]`) and the host can classify text with the same calibrated numbers as the HTTP API. The protocol core (`handle_message`) is pure and unit-tested — no JSON-RPC plumbing leaks into the Worker.

The GET form is the browser-friendly, keyless route an agent reaches by URL
construction alone:

```sh
curl 'https://your-worker.workers.dev/urgent,quick-and-easy,RFC2119/we-need-this-today'
```

## Judging the math (read this before trusting a number)

Measured numbers live in `eval/results/`; the recipe is in `eval/README.md`.
The fit is on the REAL deployed embedder (`@cf/baai/bge-small-en-v1.5`, via
`scripts/train_bge.py`): fit on 44 calibration records — single-label
temperature `0.10` (NLL 0.826), multi bias `1.54` / temperature `0.55` /
threshold `0.14` (train F1 `0.69`). Judged on the 15-record eval holdout:
single accuracy `0.70`, reliability `0.40`, multi F1 `0.08`. The multi numbers
are honest but small: the eval set is news topics while the calibration set
was movement commands, and the fit is 44 records. The threshold lesson holds:
the `0.142` boundary is co-fit with F1, because a fixed 0.5 boundary silently
returned F1 0. `GET /benchmark` serves these measured numbers from a module
that only `train_bge.py` writes, so nothing is typed into docs by hand.
